## 1. 프로젝트 = 워크스페이스 ★ 먼저 — **1단계 구현됨 (2026-10-07)**

> 로컬 프로젝트 모델·시작 화면·프로젝트 탭 줄, 그리고 1.3 의 Dropbox 매핑(열 때 한 번만
> 맞추기, 자동 사본 금지, 임시 워크스페이스 정리)까지 들어갔다.
> 남은 것은 **프로젝트 단위 내보내기/불러오기**(§5-5 와 함께).

### 목표
워크스페이스 하나 = **작품 하나**. 그 안의 도안 탭들은 그 작품을 만드는 데 필요한 조각들
(인형: 머리·몸통·다리 A/B · 옷: 앞판·뒤판·소매). 작품 사이는 **도안 탭 줄 위의 프로젝트 탭**으로 오간다.

### 범위
- 로컬에서도 프로젝트 여러 개를 만들고·이름 바꾸고·복제하고·지우고·전환한다 (Dropbox 없이).
- 도안 탭 줄 위에 **프로젝트 탭 줄**. 좁은 화면에서는 드롭다운으로 접는다.
- **시작 화면** — 서비스를 열면 어떤 프로젝트를 열지 먼저 고른다.
- 저장 포맷 v4 + 마이그레이션, Dropbox 매핑, 파일 내보내기/불러오기 정리.
- **동기화 충돌·임시 워크스페이스 문제 해소** (아래 1.3).

### 설계 메모
```ts
interface Project {
  id: string;
  name: string;            // "토끼 인형"
  tabs: Tab[];             // 도안들 (머리·몸통·다리…)
  activeTabId: string;
  note?: string;           // 실·바늘·사이즈 메모
  createdAt: string;
  updatedAt: string;
}
interface Workspace { projects: Project[]; activeProjectId: string; }
```
- **이미 있는 것**: Dropbox 동기화는 벌써 "이름 붙은 워크스페이스 여러 개"(`/workspaces/<id>.json`,
  `workspaceList`, `switchWorkspace`, `createWorkspace`)로 되어 있다. 프로젝트 1개 = 그 파일 1개로
  그대로 매핑하면 동기화 설계를 다시 짤 필요가 없다. 지금 비어 있는 건 **로컬 다중 프로젝트**뿐이다.
- **마이그레이션**: v3(탭 배열) → 프로젝트 하나로 감싼다. 이름은 첫 탭 이름 또는 `내 작품`.
  읽기는 관대하게(기존 규칙 유지) — 모양이 이상한 프로젝트만 건너뛴다.
- **저장 키**: `crochet-chart:workspace` 유지(안에 프로젝트 배열). 깨진 데이터 백업 키도 그대로.
- **내보내기**: ① 프로젝트 전체 `.json`(작품 한 벌) ② 도안 하나 `.json`(지금 것) 둘 다 둔다.
  불러오기는 둘을 자동으로 가린다.
- **읽기 모드 진행 상황**은 탭마다 유지(지금과 같음). 프로젝트 전환 시 각자 자리로 돌아온다.
- UI: 프로젝트 탭 = 작품 이름 + 도안 수 뱃지, `+` 로 새 작품. 탭 오른쪽 클릭(또는 ⋯)으로
  이름 바꾸기·복제·삭제·내보내기.

### 1.1 시작 화면 — 어떤 작품을 열까

앱을 열면 **아무 프로젝트도 자동으로 열지 않는다**. 대신 목록을 보여 준다.

```
  ┌ 작품 고르기 ─────────────────────────────┐
  │  토끼 인형      도안 4개   어제           │
  │  라글란 스웨터  도안 3개   3일 전  ☁ 최신 │
  │  수세미 모음    도안 7개   지난주  ☁ 원격이 더 새것 │
  │                                           │
  │  + 새 작품        📂 파일에서 불러오기     │
  └───────────────────────────────────────────┘
```
- 각 줄: 이름 · 도안 수 · 마지막으로 연 시각 · 동기화 상태(`☁ 최신` / `원격이 더 새것` / `이 기기에만`).
- 마지막에 열던 작품은 맨 위에 두고 Enter 로 바로 열 수 있게 한다 (늘 고르게 하면 성가시다).
- "이어서 작업" 바로가기는 두되, **자동으로 열리지는 않는다** — 열리는 순간이 곧 동기화를
  결정하는 순간이라, 사용자가 그 순간을 보고 있어야 한다.

### 1.2 로컬 저장 구조

지금은 로컬에 **열려 있는 워크스페이스 하나**만 있다(`crochet-chart:workspace`). 이것이
"지금 로컬 내용이 어느 프로젝트의 것인지" 를 잃게 만드는 뿌리다. 바꾼다:

```
crochet-chart:projects            프로젝트 목록(메타: id·이름·도안 수·마지막 연 시각·rev)
crochet-chart:project.<id>        프로젝트별 내용 (지금의 워크스페이스 한 벌)
crochet-chart:open                지금 열어 둔 프로젝트 id (없으면 시작 화면)
```
- 프로젝트마다 **마지막으로 받은 원격 rev** 를 함께 저장한다 → 열 때 로컬/원격 중 어느 쪽이
  새것인지 바로 판단할 수 있다.
- 기존 `crochet-chart:workspace` 는 마이그레이션 때 프로젝트 1개로 옮기고 그대로 남겨 둔다(백업).

### 1.3 동기화 — 지금 왜 꼬이는가, 어떻게 푸는가

**지금**: 로컬 워크스페이스는 전역으로 하나인데 `activeWorkspaceId` 는 Dropbox 파일을 따로
가리킨다. 그래서 (a) 다른 기기에서 작업한 뒤 돌아오면 로컬의 오래된 내용이 어느 파일의 것인지
모른 채 올라갈 수 있고, (b) 충돌을 "둘 다 두기" 로 풀면 `… (사본)` 워크스페이스가 새로 생긴다.
이것이 **임시 워크스페이스가 쌓이는** 경로다.

**바꿀 규칙**
1. **열 때 한 번만 맞춘다.** 프로젝트를 여는 순간 원격 rev 와 로컬 rev 를 비교해
   - 같으면 그냥 연다,
   - 원격이 새것이면 받아서 연다,
   - 로컬이 새것이면 올리고 연다,
   - **양쪽 다 바뀌었을 때만** 시작 화면에서 묻는다(원격으로 열기 / 내 것으로 덮기 / 둘 다 두기).
   작업 도중에 묻지 않으므로 "뜨다가 갑자기 뜨는 충돌 창" 이 사라진다.
2. **열려 있는 프로젝트만 올린다.** 다른 프로젝트는 건드리지 않는다 (지금은 전역 상태가
   활성 파일로 흘러 들어간다).
3. **사본은 사용자가 고를 때만** 만든다. 자동으로 `(사본)` 을 만들지 않는다.
4. 사본을 만들면 **그 자리에서 이름을 받는다** — 이름 없는 임시 워크스페이스를 남기지 않는다.
5. 이미 쌓인 임시 워크스페이스는 시작 화면에서 **정리**할 수 있게 한다 (여러 개 골라 삭제).

### 영향
`stores/tabs.ts`(workspace 구조 전체), `lib/persistence.ts`(v4·검증·마이그레이션),
`stores/dropboxWorkspace.ts`(프로젝트↔파일 매핑), `components/TabBar.svelte`(+ 새 `ProjectBar.svelte`),
`WorkspaceMenu.svelte`(프로젝트 탭으로 역할 이동), `App.svelte` 레이아웃.

### 크기 — **L**

### 완료 기준
- 프로젝트 2개를 만들어 각각 도안 3개를 넣고, 전환·새로고침·Dropbox 동기화 후에도 그대로.
- 기존 사용자의 v3 데이터가 프로젝트 1개로 열린다 (데이터 손실 0).
- 도안 탭 동작(추가·복제·닫기·순서)은 그대로.
- 앱을 열면 시작 화면이 뜨고, 마지막 작품을 Enter 로 바로 열 수 있다.
- 두 기기에서 같은 프로젝트를 고쳐도 **작업 도중에 충돌 창이 뜨지 않는다** — 열 때 한 번만 묻는다.
- 자동으로 생기는 `(사본)` 워크스페이스가 없다.

## 2. 코 세는 규칙을 설명서 기준으로 — **구현됨 (2026-10-07)**

### 목표
`pattern_writer_study.md` §7.2 의 **셈법 차이 3가지**를 설명서 쪽으로 맞춘다.

| 항목 | 지금 | 바꿀 것 |
|---|---|---|
| 단 끝 빼뜨기 | 1 → 1 코로 셈 | **코 수에서 제외** (단 중간 빼뜨기는 그대로 셈) |
| 기둥코 1 | 1코로 셈 | **안 셈** (0 → 0). 기둥코 2~5 는 지금처럼 1코 |
| 기둥코 (추가) | 표기 없음 | 기초코를 차지하지 않고 **따로 그려지며 1코** |
| `사이사슬 2, 2코 스킵` | 방금 만든 사슬을 건너뜀 | **아래 단 코**를 건너뜀 |

### 설계 메모
- 단 끝 빼뜨기: "그 단의 **마지막** op 가 SLIP" 일 때만 0 → 0 으로 본다. 판정은 expander 뒤
  (`resolveRounds` 자리)에서 하면 파서를 건드리지 않는다.
- 기둥코: `tc(O)` = 1코짜리 → 0 → 0, `tc(3O)` → 1 → 1(지금과 같음).
  **추가 기둥코**는 새 표기가 필요하다 → `tc+(3O)` 제안 (기초코를 소비하지 않고 1코를 만든다).
- 사이사슬/연결사슬: 설명서는 **사이사슬(코 수 제외)** 과 **연결사슬(코 수 포함 + 아래 코 스킵)** 을
  구분한다. 우리는 둘 다 `O` 라서 생기는 문제다. 표기 추가가 필요하다:
  - `cs2` 사이사슬 2 (아치, 코 수 제외)
  - `lc2` 연결사슬 2 (코 수 포함, 아래 코 2개 스킵)
  그리고 `skip(N)` 은 **부모 코**를 건너뛰도록 되돌린다. 단 안에서 만든 사슬 위에 뜨는 그물뜨기는
  `cs` 가 생기면 그쪽으로 표현하면 되므로, 지금의 "사슬을 부모로 쓰는 큐" 는 `cs` 전용으로 좁힌다.
  → **이 항목만 설계가 더 필요**하다 (기존 도안 호환 포함).
- 기존 도안의 코 수 라벨이 바뀐다 → **그대로 바꾼다**(2026-10-07 결정). 호환 옵션은 두지 않는다.
  바꾸기 전에 회귀 테스트로 "바뀌는 자리" 를 먼저 고정한다.

### 영향
`lib/validate.ts`, `lib/expand/expander.ts`(또는 resolveRounds), `crafts/crochet/parser.ts`(새 표기),
`crafts/crochet/stitch.ts`, 레이아웃(스킵 의미), 문서·도움말, `tests/pattern-writer-coverage.test.ts`.

### 크기 — **M** (사이사슬/연결사슬만 따로 떼면 S + M)

### 완료 기준
`pattern-writer-coverage.test.ts` 의 "셈법이 다른 것" 묶음이 **"설명서와 같다"** 로 바뀐다.

## 3. 걸어뜨기 — 걸 코 지정 · 이어서

### 목표
`한길긴뜨기 앞걸어뜨기 1단 2번째 코` / `… 이어서` 를 적을 수 있게 한다. 골지·꽈배기에서
2단 아래 기둥에 거는 도안이 제대로 그려진다.

### 범위
- 표기 제안: 코 뒤에 `@단-코` — `fpF@1-2` (1단 2번째 코), 이어서는 `fpF@^`
  (가장 가까운 아래 단의 걸어뜨기에 잇는다). 한글 표기는 쓰지 않는다(토크나이저 일관성).
- Op 에 `target?: { round: number; stitch: number } | 'nearest'`.
- 레이아웃: 그 코를 부모로 삼아 위치를 잡고, 아래 단까지 **점선 연결선**을 그린다.
- 없는 자리를 가리키면 설명서처럼 **조용히 보통 걸어뜨기로** 그리되, 편집기에 경고 한 줄.

### 설계 메모
- 부모 지정은 `parentIndices` 를 덮어쓰는 방식 — 레이아웃의 "순차 부모 배정" 뒤에 보정 단계를 둔다.
- `@^` 는 **아래로 훑어** 같은 열에서 가장 가까운 걸어뜨기를 찾는다. 중간에 다른 단이 끼어도 잇는다.
- 세로 연결선은 캔버스 선택 대상(`data-el`)으로도 등록해 손으로 옮길 수 있게 한다.

### 영향
`crafts/crochet/parser.ts`, `expand/op.ts`, `crafts/crochet/{flat,circular}.ts`, `svg.ts`, 문서.

### 크기 — **M**

### 완료 기준
`tc(3O), fpF@1-2, 10F` 가 1단 2번째 코에 걸린 모양으로 그려지고, 윗단 `fpF@^` 가 그 아래
걸어뜨기로 이어진다. 코 수 검증은 그대로.

## 4. 조각 · 잇기 · 나누기 — **1단계 구현됨 (2026-10-08)**

> 조각 관계(잇기·이어받기)와 **코 수 계산·검증**이 들어갔다. 남은 것은 **합쳐 그리기**
> (몸통 도안에 조각들이 나란히 그려지는 것) — 레이아웃이 뿌리 하나를 전제해서
> 여러 뿌리를 두는 작업이 필요하다 (§4-b).

### 목표
인형처럼 **여러 조각을 따로 뜨고 합치는** 도안을 한 작품 안에서 표현한다.

### 결정 (2026-10-07)
**(B) 도안 탭 = 조각** 으로 간다. 아래 두 갈래 설명은 근거로 남긴다.
- **(A) 한 도안 안에서** — 설명서 방식. 이름 줄(`다리 B`)로 조각을 나누고 `잇기 사슬코 4` 로 합친다.
  한 캔버스에 조각들이 나란히 그려진다.
- **(B) 프로젝트의 다른 도안 탭을 조각으로** — 탭 하나 = 조각 하나. 몸통 탭이
  `잇기(다리 A, 다리 B, 사슬 4)` 로 두 탭을 가져와 그 위에 이어 뜬다.
  프로젝트 모델과 맞고, 조각마다 읽기 모드·메모·게이지가 따로 간다.

→ **(B) 로 정했다.** 다만 그리기는 (A)와 같아야 한다(합쳐진 그림 한 장) — 몸통 탭의 도안에
참조한 조각들이 함께 그려진다.

### 4-a 구현된 것 (2026-10-08)

**텍스트 문법이 아니라 도안의 메타데이터**로 뒀다 — 탭 이름을 바꿔도 끊기지 않도록
탭 **id** 로 가리킨다 (`lib/model/pieces.ts`, `Tab.startsFrom`).

| 시작 방식 | 뜻 |
|---|---|
| 혼자 시작 | 기본 |
| **조각 잇기** | 조각 여럿 + 사이 사슬 → 몸통. `코 수 = 조각 합 + 사슬 × 잇는 자리` |
| **이어받기** | 다른 도안에서 물려받는다 (나누기). 코 수를 일부만 가져올 수 있다 |

- 편집기 머리에 `다리 A + 다리 B + 사슬 4×2 = 44코` 칩이 뜨고, 클릭하면 고른다.
- 첫 단이 **물려받은 코 수**와 맞는지 검증한다 ("이어받은 조각의 44코 중 40코만 …").
- 가리킨 도안이 사라지면 알려 주고, 서로 물고 도는 참조(`hasCycle`)도 가려낸다.

### 4-b 남은 것 — 합쳐 그리기

몸통 도안에 조각들이 **나란히** 그려지고 사슬로 이어진 모양이 한 장에 나와야 한다.
지금 레이아웃은 뿌리가 하나라(1단이 하나) 여기서 손이 가장 많이 간다. 방향:
조각마다 따로 레이아웃한 뒤 좌표를 옮겨 합치고(조각 A 왼쪽·B 오른쪽), 몸통은 그 위에
얹는다. 조각 사이 사슬은 연결선으로 긋는다.

### 설계 메모 (B 기준)
- 첫 줄 지시문: `잇기(다리A, 다리B, 4O)` / 사슬 없이 `잇기(다리A, 다리B)`.
  같은 조각 두 벌이면 `잇기(다리A, 다리A, 4O)` 로 적어도 되고, 한 번만 적으면 한 벌 더 뜬 것으로 본다.
- `나누기(3)` — 이 단에서 N 갈래로 나뉜다. 갈래는 **새 탭**으로 만들어지고, 각 탭의 첫 줄이
  `이어받기(몸통, 6단, 10코부터)` 를 갖는다. 나누며 남기는 코 수도 적는다.
- 코 수: 몸통 = 조각들의 코 수 합 + 사슬 × 2 (설명서 5-2-1 과 같은 규칙) — 자동 계산해 검증.
- 레이아웃: 조각들을 **나란히 배치**한 뒤 몸통을 그 위에 얹는다. 평면 레이아웃에 "여러 뿌리" 개념이
  필요하다 — 지금은 1단이 하나뿐인 전제라 여기서 손이 가장 많이 간다.
- 라벨: 조각 이름이 도안에 붙고, 캔버스에서 옮길 수 있어야 한다(`data-el`).

### 영향
`stores/tabs.ts`(탭 간 참조·파생), 새 `lib/model/pieces.ts`, 평면 레이아웃, 렌더러, 검증, UI(탭 메뉴).

### 크기 — **L** (프로젝트 모델 1 이 먼저 끝나야 함)

### 완료 기준
다리 A/B 두 탭 + 몸통 탭으로 인형 아랫부분을 그리면, 몸통 도안에 두 다리가 나란히 그려지고
사슬로 이어진 모양이 나온다. 코 수 검증 통과.
